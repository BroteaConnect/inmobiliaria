# Bilingual showcase (es/en) — the i18n layer

The public landing ships in Spanish and English on the factory i18n
contract (feature 52). Spanish is the default and keeps every existing
URL; English lives under a locale prefix:

| URL | Locale | Built file |
|---|---|---|
| `/` | `es` (default, unprefixed) | `dist/index.html` |
| `/en/` | `en` | `dist/en/index.html` |

Property **data is never translated**: `titulo`, `municipio` and
`descripcion` come from PocketBase and render as typed (Spanish) on both
pages. Only UI copy (chrome, labels, statuses, aria-labels) is localized.
The internal lead notification POSTed to `api.brotea.dev/requirements`
also stays in Spanish — it is a Telegram message to the team, not copy.

## Locale files (`src/locales/`)

```
src/locales/
  config.json        locales, defaultLocale, required, native names, dir, Intl tags
  es.json            flat, alphabetically sorted key → string map
  en.json            same key set as es.json (CI-enforced)
  locales.test.mjs   the CI gate (GENERATED — see below)
```

`config.json` as merged: `defaultLocale: "es"`, `locales: ["en","es"]`,
`required: ["en","es"]` (both languages are gated), `intl` maps `es` →
`es-ES` and `en` → `en-GB` for all `Intl` formatting. `brotea.json`
carries the matching `i18n` block (`runtime: "1.0.0"`).

Dictionary keys are flat and dot-namespaced (`nav.home`, `form.submit`,
`gallery.photoAlt`). Placeholders use `{name}` syntax and plural stems
store one entry per CLDR category:

```json
"card.meta": "{rooms} hab · {baths} baños · {area} m²",
"card.photos.one": "{count} foto",
"card.photos.other": "{count} fotos"
```

## The runtime: `src/lib/i18n.ts`

Zero-dependency module; dictionaries are inlined at build time via
`import.meta.glob`, so it works identically server-side and in the client
bundle (no runtime fetch). Main exports:

- `t(locale, key, vars?)` — translate + interpolate. `vars.count` selects
  the plural form via `Intl.PluralRules`. A key missing (or empty) in the
  locale falls back to the default locale, then to the key itself — it
  never throws.
- `tt(locale)` — binds `t` to a locale: `const _ = tt(locale); _('nav.home')`.
- `localePath(locale, path)` — `localePath('en', '/')` → `/en/`;
  `localePath('es', '/')` → `/` (default locale is unprefixed).
- `localeFromPath(pathname)` / `stripLocale(pathname)` — resolve/remove
  the locale prefix of a URL.
- `localePaths()` — `getStaticPaths` helper: emits `lang: undefined` for
  `es` and `lang: 'en'` for English, with `locale` as a page prop.
- `alternates(path)` — hreflang link data for `<head>`.
- `fmtNumber` / `fmtMoney` / `fmtDate` — `Intl` formatting per locale
  (see below).

**Generated file**: `i18n.ts`, `LanguageSwitcher.astro` and
`locales.test.mjs` are copied in by `brotea new` / `brotea i18n sync`.
Never hand-edit them here — fix `i18n/runtime/` in the factory and
re-sync (same rule as `theme.css`).

## Routing: `src/pages/[...lang]/index.astro`

The single page moved from `src/pages/index.astro` to
`src/pages/[...lang]/index.astro`:

```astro
---
import Layout from '../../layouts/Layout.astro';
import { localePaths, t } from '../../lib/i18n';

export const getStaticPaths = localePaths;
const { locale } = Astro.props;
---
<Layout locale={locale}>
  <h1>{t(locale, 'hero.title')}</h1>
```

One file generates both HTML pages; adding a language to `config.json`
generates its pages with no new files.

### Locale in the client script

Astro bundles the page `<script>` **once** for every generated route, so
the locale cannot be compiled in. It is resolved from the URL at runtime
— the same source the pages were generated from:

```ts
import { fmtMoney, localeFromPath, t } from '../../lib/i18n';
const locale = localeFromPath(location.pathname); // '/' → es, '/en/…' → en
const _ = (key, vars) => t(locale, key, vars);
```

All JS-created DOM (catalog cards, gallery, dialog, form statuses) goes
through `_()`. Note the CI gate checks dictionaries, not call sites: a
hardcoded string in the script ships Spanish on `/en/` without failing
CI — smoke-test both pages when touching that script.

## `<html>` metadata and hreflang (`src/layouts/Layout.astro`)

The layout takes a `locale` prop (defaults to `DEFAULT_LOCALE`) and emits:

- `<html lang={locale} dir={dirOf(locale)}>`;
- `<title>` and meta description from `t(locale, 'page.title' /
  'page.description')` (the old `title` prop is gone);
- one `<link rel="alternate" hreflang=…>` per locale via `alternates()`,
  plus an explicit `x-default` pointing at the Spanish path. URLs are
  absolute because `astro.config.mjs` now sets
  `site: 'https://inmobiliaria.brotea.dev'`.

## LanguageSwitcher (`src/components/LanguageSwitcher.astro`)

Mounted inside `Nav.astro`'s `.links`, after the `<!-- brotea:nav -->`
marker. It links to the **same page** in every shipped locale
(`localePath(code, stripLocale(Astro.url.pathname))`), so switching
language never sends the visitor back to the home page. The current
locale's link carries `aria-current="true"`; labels are the native names
from `config.json` (`Español` / `English`); the `<nav>` aria-label is
`t(locale, 'nav.language')`. Token-only styling.

## Prices and dates via `Intl`

The hand-rolled `eur()` helper is gone; prices use the runtime:

```ts
fmtMoney(locale, p.precio, 'AED')
// es → "1.234.567 AED"      en → "AED 1,234,567"
```

`fmtMoney` pins `maximumFractionDigits: 0`. `fmtDate(locale, d)` exists
in the runtime but has no call sites yet — there are no user-facing
dates in `src/` (date logic lives in `jobs/`, which is backend and stays
Spanish by factory policy).

## CI gate: `src/locales/locales.test.mjs`

`npm test` (and therefore CI) now runs:

```
node --test jobs/*.test.mjs src/locales/*.test.mjs && astro build
```

For every `required` locale (here: both) the gate asserts:

- every declared locale has a dictionary and vice versa;
- same key set as the default locale, no empty values, no extra keys;
- keys alphabetically sorted (stable diffs);
- placeholders survive translation (`{count}` dropped ⇒ red);
- plural stems keep `.other` plus every category the language needs per
  `Intl.PluralRules` (`.one` for both es and en).

A single missing or unsorted key blocks the merge. `astro build` doubles
as the "both routes still build" check.

## Adding a language

```
brotea i18n add <code>          # from the factory root
```

This registers the locale in `config.json` and creates
`src/locales/<code>.json` with empty values. While the locale is in
`locales` but not in `required`, `t()` falls back to Spanish and the gate
does not block deploys; promote it to `required` when translation is
complete. Verify coverage anytime with `brotea i18n check --app <path>`.
